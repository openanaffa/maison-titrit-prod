# Backup & R2 — Maison Titrit (2026-11-18)

## 1. Image uploads — fixed ✅

**Root cause:** `useUploadImage` (in `web/src/hooks/api/products.ts:53`) calls `POST /api/admin/upload`, but **no such route existed**. Every admin image upload returned 404.

**Fix:** Added `web/src/app/api/admin/upload/route.ts`:
- `POST /api/admin/upload` — requires `products:write` permission (FOUNDER / DEVELOPER / ADMIN)
- Parses `multipart/form-data`, delegates to `saveUpload()` from `web/src/lib/storage.ts`
- `saveUpload()` detects R2 via `R2_*` env vars → uploads to Cloudflare R2 (S3 API); falls back to local disk `/public/uploads` (dev only — ephemeral on Vercel)

Also added by parallel work: `web/src/app/api/admin/upload/blog/route.ts` — `POST /api/admin/upload/blog` with `content:write` permission (FOUNDER / DEVELOPER / ADMIN / MARKETER) for blog cover images.

**.gitignore:** un-ignored `web/src/app/api/admin/upload/` so the route is committed.

## 2. R2 env vars required for production image uploads

Production image persistence requires these set in **Vercel → Project → Settings → Environment Variables**:

| Variable | Value | Source |
|----------|-------|--------|
| `R2_ACCOUNT_ID` | Cloudflare account ID | Cloudflare dashboard → R2 |
| `R2_BUCKET` | `maison-titrit` | R2 bucket name |
| `R2_ACCESS_KEY_ID` | S3-compatible access key | R2 → Manage R2 API Tokens |
| `R2_SECRET_ACCESS_KEY` | S3-compatible secret key | R2 → Manage R2 API Tokens |
| `R2_PUBLIC_URL` | `https://cdn.maisontitrit.com` | R2 → Public access → custom domain |

Without these, `r2Config()` returns `null` and uploads fall back to local disk — which is **ephemeral on Vercel** (images disappear on redeploy). That's the production failure mode.

**DNS (terraform/):** `CNAME cdn → <bucket>.r2.dev` for `cdn.maisontitrit.com`. `terraform.tfstate` and `terraform.tfvars` are gitignored.

## 3. Nightly database backup (db-backup)

**Schedule:** 02:17 UTC daily (cron `17 2 * * *`), plus `workflow_dispatch` for manual runs.

**What it does:**
1. `pg_dump` (postgres:17) of Supabase `public` schema → `dump.pgc`
2. Validates ≥10 tables with data (fails otherwise)
3. Encrypts with `age` (public key hardcoded in workflow; identity in `pass maison-titrit/backup/age-identity`)
4. Uploads `dump.pgc.age` to R2 bucket `maison-titrit-backups` under `db/YYYY/MM/DD/`
5. R2 lifecycle rule `expire-db-30d` → objects expire after 30 days

**Required GitHub Actions secrets** (repo Settings → Secrets and variables → Actions):

| Secret | Value | Notes |
|--------|-------|-------|
| `BACKUP_DATABASE_URL` | Session pooler URL | `aws-0-eu-west-1.pooler.supabase.com:5432`, user `postgres.<project-ref>`, `sslmode=require`. **Needs rotation** — see §4. The direct `db.*.supabase.co` host is IPv6-only and unreachable from Actions. |
| `R2_BACKUP_ACCESS_KEY_ID` | R2 API token | Scoped to `maison-titrit-backups` bucket only |
| `R2_BACKUP_SECRET_ACCESS_KEY` | R2 API token secret | Paired with above |
| `R2_ACCOUNT_ID` | Cloudflare account ID | Same as image upload R2 |

**Run one now:** GitHub → Actions → db-backup → Run workflow.

**Restore** (into a scratch database first, never straight over prod):

```sh
aws s3 cp s3://maison-titrit-backups/db/<date>/<file>.pgc.age . \
  --endpoint-url https://<account-id>.r2.cloudflarestorage.com
age -d <file>.pgc.age -o <file>.pgc
pg_restore --clean --if-exists --no-owner --no-privileges -d <scratch-db> <file>.pgc
```
