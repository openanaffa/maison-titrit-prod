# #126 — End-to-end tests for checkout, COD, inventory and RBAC

Parent: #114 (P0). Covers paths introduced by #111 and #112.

## Verified current state
- No Playwright/E2E anywhere; CI is a single `verify` job (`bun test` unit only).
- Auth: Supabase (`supabase.auth.getUser()`); role resolution reads the app's
  own `User` table via `supabaseId` (`requesting_user_role()`), so a **local
  Supabase instance** yields full staff E2E with zero production contact.
- Checkout: `/produit/[ref]` → cart drawer → `/checkout` → `CheckoutSuccess`
  with the order number; delivery zone matched case-insensitively by city.
- Reservation/settlement ledger conventions from #148 (RESERVE movements,
  `checkout:<idempotencyKey>:reserve:*`, settlement suffixes).

## Design

### Isolation architecture
- **CI (authoritative run)**: local Supabase via CLI + Docker on
  `ubuntu-latest` (separate `e2e` CI job so `verify` stays fast).
  `supabase db reset` applies `supabase/migrations/*.sql`; Prisma pushes the
  postgres schema to the local instance; deterministic seed; the app runs
  against `http://127.0.0.1:54321` with the local anon/service keys from
  `supabase status`. **Nothing production is contacted.**
- **Local (no Docker)**: guest paths run against the SQLite dev database
  (`file:` URL) — guest specs stay runnable; staff specs auto-skip.
- **Production guard**: the seed refuses to run unless `DATABASE_URL` is the
  local Supabase Postgres or a `file:` database, and the seeded auth users
  are created only against a `127.0.0.1` Supabase URL.

### Deterministic seed (`web/e2e/seed.ts`, `bun run e2e:seed`)
- Products: one with variants (`S/M/L`, on-hand per size, one size sold out),
  one legacy sizeless product with product-level availability, one
  out-of-stock product.
- One active delivery zone covering the seeded city with a fixed fee.
- Staff account (FOUNDER) + customer account auth users (password sign-in)
  with matching `User` rows.

### Specs (Playwright, chromium, `web/e2e/*.spec.ts`)
1. `guest-checkout.spec.ts` — storefront → product → cart → checkout form →
   success page with order number; **persisted-state assertions**: Order row
   (PENDING, total incl. delivery fee), OrderItem rows, RESERVE
   StockMovement, OrderStatusHistory.
2. `variants.spec.ts` — variant size selection on the product page;
   unavailable size blocked; sold-out variant un-purchasable; legacy
   sizeless product still purchasable via product-level availability.
3. `duplicate-submission.spec.ts` — two parallel POSTs with the same
   idempotency key create exactly one order; double-click submit creates
   one order.
4. `staff-transitions.spec.ts` — staff signs in locally, processes the
   seeded order end-to-end in the fulfilment queue
   (PENDING→CONFIRMED→PROCESSING→DISPATCHED→DELIVERED); asserts status
   history rows, audit trail, and inventory settlement (reservation released
   on a cancelled branch order; committed on the delivered order).
5. `rbac.spec.ts` — anonymous `/makteb/*` redirects to sign-in; anonymous
   admin API PATCH/POST get 403; a CUSTOMER session hitting
   `customers:write` APIs gets 403; staff pages stay reachable for staff.

### CI wiring
- New `e2e` job in `.github/workflows/ci.yml`: Docker present on runners,
  `supabase/setup-cli`, `supabase start` (core services only),
  `supabase db reset`, seed, `bunx playwright test`, upload the report
  artifact on failure. Playwright browsers cached via `actions/cache`.
- `@playwright/test` + `pg` added to `web` devDependencies with
  **Bun 1.3.14** (lockfile stays `lockfileVersion: 1`).

## Acceptance mapping
- Critical paths in CI, isolated DB → CI e2e job + local Supabase/SQLite.
- Persisted-state assertions → specs 1/2/4 query the database directly.
- Failure and retry scenarios → specs 2/3 (sold-out, duplicate submit,
  replayed idempotency) + settlement re-run.
- Deterministic, never production → seed guard + local-only URLs.

## Out of scope
- Accessibility/CWV (#127), monitoring/restore (#128). Wafine integration and related E2E coverage (#123–#125) were cancelled as Not planned because Wafine does not use the official WhatsApp API.
